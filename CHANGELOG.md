# Changelog

Все заметные изменения «Платформы Голос» (https://github.com/gradosphera/blago-vote).

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [1.10.0] - 2026-09-07

### Исправлено

- **Обновлённые метаданные ДАО (аватар, название и т.п.) не отображались в интерфейсе после обновления через «Настройки».** Причина: фронт по умолчанию рендерит данные с индексёра `api.ton.vote`, а он не отразил смену указателя метаданных ДАО (отдавал старую запись с аватаром, который больше не доступен). Единовременный запас в 90 секунд (чтение с контракта после обновления) не спасал: как только индексёр «догонял» по своему внутреннему времени, интерфейс снова возвращался к его (устаревшим) данным. Теперь после обновления интерфейс сверяет адрес метаданных из индексёра с фактическим указателем на цепочке (`compareDaoMetadataWithChain` в `src/query/hooks.ts`): пока они расходятся, страница ДАО (`src/query/getters.ts`) и списки/сайдбар (`useIsDaosUpToDate`) показывают данные прямо с контракта, а локальная метка снимается только при реальном совпадении адресов — обновлённый логотип не откатывается назад.

## [1.9.0] - 2026-09-04

### Исправлено

- **Окно подключения кошелька не открывалось вовсе** (после клика по кнопке «Кошелек» «ничего не происходило» и локально, и на проде). Причина: TonConnect SDK по умолчанию загружает список кошельков с `https://config.ton.org/wallets-v2.json`, который в ряде сетей недоступен — SDK замирает на инициализации, и модальное окно не рендерится. Создан собственный коннектор (`src/tonConnect.ts`), который подставляет локальную копию реестра кошельков `public/wallets-v2.json` (загружается с того же домена, что и приложение; в `src/main.tsx` в провайдер передан `connector`). `@tonconnect/sdk` добавлен прямой зависимостью.

### Добавлено

- **Выпадающее меню кошелька после авторизации** (`src/layout/Navbar.tsx`). Клик по кнопке «Кошелек» при подключённом кошельке открывает стандартное меню: имя кошелька и полный адрес, пункты «Скопировать адрес» (копирует в буфер обмена с уведомлением «Скопировано») и «Выйти» (отключение от кошелька).

## [1.2.0] - 2026-09-02

### Кратко

Telegram-бот теперь устойчиво подключается к Bot API даже в сетях с блокировкой Telegram — через **собственный Cloudflare Worker-релей**, и готов к локальному запуску на Ubuntu.

### Инфраструктура / развёртывание (Telegram-бот)

- **Обход блокировки Telegram через свой Cloudflare Worker-релей** (`bot/cf-api-relay/`)
  - Воркер `worker.js` + конфиг `wrangler.toml`: проксирует `api.telegram.org` на адрес `*.workers.dev`. Сеть Cloudflare доступна там, где заблокирован Telegram (весь диапазон IP Telegram закрыт), а токен бота не попадает третьим лицам — трафик идёт только через собственный воркер.
  - Включается переменной `TELEGRAM_API_BASE` в `bot/.env`; в логе пишется `Telegram API host: <адрес> (релей)`.
  - Воркер изолирует беспорядок HTTP-заголовков Cloudflare: вырезает `content-length`/`content-encoding` и hop-by-hop заголовки, читает тело апстриима целиком (`arrayBuffer`), ставит внутренний таймаут 15 с и отдаёт собственный JSON (`502`) с диагностическими заголовками `x-upstream-status/bytes/error`, если апстриима завис — никаких зависших запросов к клиенту.
  - **Бот-сторона (устойчивость к нестабильной сети):** уменьшен таймаут запроса (60→40 с) и добавлены ретраи (2) с паузой при транзиентных сетевых сбоях. Ключевой фикс: при зависшем теле (заголовки 200 уже пришли, но байты не дошли — симптом DPI на `*.workers.dev`) запрос теперь **всегда** повторяется: раньше частичный ответ принимался за прикладной, и ретрая не было.
- **Локальный запуск на Ubuntu** — раздел «Быстрый старт» в `bot/README.md` и обновлённый `bot/.env.example` (включая инструкцию 0.1 по Cloudflare Worker-релею и проверку `curl`'ом).
- **Диагностика при старте**:
  - `validateConfig()` — проверка конфигурации перед запуском.
  - `checkProxyReachable()` — быстрая проверка доступности SOCKS5-прокси (fail-fast) с понятным выводом (`Proxy OK: …` / `недоступен … гост gost`).
  - Финальная ошибка подключения теперь содержит `BOT_TOKEN`/`proxy`/номер попытки — не «слепое» сообщение.
- **Упрощена конфигурация:** `PROXY` по умолчанию пуст (прямое подключение) вместо жёсткого `socks5h://127.0.0.1:9100`; появилась `TELEGRAM_API_BASE` (по умолчанию `https://api.telegram.org`).

### Исправлено

- **Футер** (текст «ДАО Градосфера» со ссылками) всегда отображается выше нижней панели и не перекрывается ей.

### Инфраструктура / развёртывание (Telegram-бот)

- **Удалена зависимость от Tor.** Бот использует любой SOCKS5-egress (чистый JS `socks-proxy-agent`, архитектурно-независим), задаётся через `PROXY` в `bot/.env` (по умолчанию `socks5h://127.0.0.1:9100`).
- **Системный сервис** `bot/blago-bot.service` (user systemd, `Restart=always`, `After=network-online.target`) — бот автозапускается и перезапускается при падении. Не зависит от Tor.
- **Шаблон edge-шлюза** `bot/gost.service`: на выделенном узле поднимается `gost` SOCKS5-листенер (порт `9100`) поверх WireGuard-туннеля к зарубежному VPS — это даёт ботам egress. Портативно для RISC-V (`gost` на Go, `wg` в ядре).
- **Устойчивость к медленному прокси:** таймаут запросов Telegram увеличен до 60 с, `getMe` повторяется до 10 раз с паузой 5 с (бот не падает сразу при кратковременной недоступности сети).

- **Tonviewer** вместо tonscan в ссылках на адреса и транзакции.
- **Страница мультикошелька**: адрес мультикошелька оформлен карточкой в стиле карточек главной страницы — аватар (логотип жетона сообщества или GRAM), название, адрес и балансы **GRAM** и жетона сообщества (например, **Благо**).
- **Линейная диаграмма порога** на странице мультикошелька в поле «Порог»: длинный прямоугольник со скруглёнными краями в стиле карточки адреса — левая половина (порог, синий) и правая (число подписантов, зелёный) с одинаковой прозрачностью; внутри каждой половины крупным жирным шрифтом — количество из порога.
- **Список заявок** на странице мультикошелька показывается постранично — 5 заявок с кнопками «Далее»/«Назад».
- **Скелетон загрузки**: перед показом данных мультикошелька на странице отображается мигающий размытый элемент размером с карточку адреса; данные появляются только после успешной полной загрузки в фоне.
- **Снижение нагрузки на API**: детали заявок (get-методы и трассы исполнения) запрашиваются только для последних 5 заявок, трассы кэшируются — заметно меньше запросов и rate limit.
- **Логотип и заголовок «Мультикошелек» в шапке** теперь ведут на главную страницу с мультикошельками сообществ с любого экрана.
- **Переименование ролей**: «предлагающие» → **инициаторы**, «подтверждающие»/«подписывающие» → **подписанты** во всех текстах интерфейса, README и CHANGELOG.
- **Мульти-провайдер с автофейловером**: toncenter → tonapi; кэш ответов, cooldown после сбоя, таймауты с понятным сообщением.
- Обновлён manifest TON Connect: название «ДАО Градосфера | Мультикошелек», корректный логотип.

### Исправлено

- **Ошибка «Invalid magic»** при разборе входящих сообщений (текстовые комментарии и сообщения в не-BOC формате больше не ломают страницу мультикошелька); тело исходящего сообщения «new_order» парсится как необязательное.
- **Ошибка «Invalid magic» при первом открытии заявки**: tonapi иногда отдаёт поля `code`/`data` аккаунта в HEX вместо base64 (а у только что созданного контракта — пустыми); теперь ячейки состояния нормализуются (hex→base64) и разбираются безопасно, с понятным сообщением вместо падения страницы.
- **Сброс страницы мультикошелька** при временных ошибках (таймаут, HTTP 5xx, rate limit, «Invalid magic»): при последующих обновлениях страница продолжает показывать последние данные, не сбрасываясь.
- **Скелетон загрузки** показывается только на странице мультикошелька: при открытии страницы заявки по прямой ссылке мультикошелек грузится в фоне без скелетона, размытый элемент не отображается на странице заявки.
- **Ошибки HTTP 500/429** теперь отображаются с понятным статусом даже при не-JSON ответе (HTML-страницы ошибок прокси/API).
- Совместимость с tonapi: корректная передача аргументов get-method (строки TVMStackValue), ячейки в hex, тип `num`, отрицательные числа.
- Endpoint транзакций tonapi; проверки трасс переведены на toncenter.
- Санитизация комментариев в заявках (защита от stored-XSS).
- Битый URL логотипа в manifest TON Connect.
- Таймауты запросов к API с понятным пользователю сообщением об ошибке.
